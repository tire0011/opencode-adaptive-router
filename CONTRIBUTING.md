# Contributing

We welcome discussion, reproducible experiments, code review and small focused pull requests.

1. Open a discussion issue with the problem, expected behavior and available non-confidential evidence.
2. For implementation changes, reference the relevant milestone in [PLAN.md](PLAN.md).
3. Keep dependencies minimal; require neither local GPU nor a paid API.
4. Add tests for policy decisions, error handling and offline behavior.
5. Avoid hardcoding model rankings or customer-specific credentials.
6. Never include proprietary source, internal endpoints, prompts or secrets in issues or test fixtures.
7. Provide benchmark methodology, sample count and limitations when claiming model quality improvements.
8. Preserve third-party license headers and attribution for reused code.

## Design feedback wanted

Especially useful: OpenCode hook compatibility, virtual model UX, eligible-model discovery, local CPU performance, enterprise provider policy enforcement, outcome attribution and statistical evaluation.

Please be respectful of maintainers' time: concise issues, concrete reproduction steps, and incremental changes are preferred.
